# 데이터 및 개인정보 정책

- 확인일: 2026-10-25
- 대상: `main`의 `605dfa4` 기준 C:V 2.0.0 소스
- 용도: 제품의 데이터 처리 설명과 개발 기준. 외부 공개용 법적 개인정보처리방침의 검토·승인 기록은 아닙니다.

## 핵심 내용

C:V는 사용자가 저장한 문장을 Chrome 프로필의 로컬 확장 저장소에 보관합니다. 계정, 서버 전송, 기기 간 동기화, 사용 분석 기능은 없습니다. C:V 자체 암호화, 백업, 휴지통, 내보내기·가져오기 기능도 없습니다.

아래 처리 설명은 현재 소스에서 확인한 동작과 유지해야 할 정책입니다. 출시된 서비스 전체에 대한 감사 결과가 아닙니다.

## 어떤 데이터를 처리하나요?

### 저장하는 데이터

현재 구현은 `chrome.storage.local`의 `cvState`에 저장합니다.

| 데이터 | 목적 | 남아 있는 기간 |
| --- | --- | --- |
| 저장 형식 버전 | 읽을 수 있는 데이터인지 판단 | 저장 데이터 삭제 전까지 |
| 리스트 ID·이름·순서 | 리스트 식별, 분류, 선택 단축키 연결 | 수정하거나 리스트를 삭제하기 전까지 |
| 문장 ID·텍스트·순서 | 문장 식별, 복사할 원문 보관, 숫자 위치 연결 | 수정하거나 문장·리스트를 삭제하기 전까지 |
| 현재 리스트 ID 또는 `null` | 웹 단축키의 대상 지정 | 선택 변경·해제 또는 해당 리스트 삭제 전까지 |

순서는 배열 순서이며 별도 순번 필드는 없습니다. 문장에는 여러 줄과 앞뒤 공백을 그대로 보관할 수 있습니다. 정확한 형식은 [아키텍처](architecture.md#저장-형식)에 있습니다.

### 잠시 처리하는 데이터

| 데이터 | 읽거나 사용하는 시점 | 처리 후 상태 |
| --- | --- | --- |
| 웹 페이지 선택 텍스트 | 사용자가 `Shift+Alt+숫자`를 누를 때 | 저장 대상 원문으로 전달. 선택 이력은 별도로 기록하지 않음 |
| 입력창의 선택 텍스트 | 같은 저장 단축키 실행 시 | 선택 구간만 사용. 비밀번호 필드는 제외 |
| 단축키 이벤트·위치 | 해당 키 이벤트 처리 시 | 일반 키 입력 기록을 만들지 않음 |
| 팝업 입력 초안 | 생성·수정 대화상자에서 편집할 때 | 저장 전에는 화면 메모리에만 존재. 팝업을 닫으면 사라짐 |
| 알림 미리보기 | 성공한 복사·저장 결과를 알릴 때 | 공백을 정리한 최대 60개 UTF-16 코드 단위를 페이지에 표시하고 1.5초 뒤 제거 |
| 오류 안내 | 요청·복사 실패 시 | 원문 대신 일반 오류 안내를 표시. 웹 오류 알림은 5초 뒤 제거 |

웹 페이지 코드는 선택 영역이 바뀔 때마다 수집하지 않습니다. 사용자가 저장 단축키를 누른 시점에만 선택을 읽습니다. 목록과 원문은 확장 내부 메시지로 전달되며, 미리보기 길이 제한은 화면 표시 제한이지 내부 원문 전달 제한이 아닙니다.

### 저장·전송하지 않는 항목

계정·연락처를 별도로 요구하지 않고, 방문 이력, 전체 페이지 본문, 일반 키 입력, 기존 클립보드 내용, 사용 분석 이벤트, 원격 오류 보고를 저장하거나 서버로 전송하는 기능이 없습니다.

페이지 실행 여부를 판단할 때 `location.protocol`을 확인합니다. 따라서 ‘URL 관련 값에 전혀 접근하지 않는다’고 설명하지 않습니다. URL을 사용자 데이터로 보관하거나 전송하는 기능은 없습니다.

## 네트워크와 동기화

현재 구현의 제품 코드에는 리스트·문장·선택 텍스트를 외부 서버로 전송하는 경로가 없습니다. `chrome.storage.sync`와 외부 API를 사용하지 않습니다. 팝업·페이지 코드·background 사이의 `chrome.runtime` 메시지는 같은 확장 프로그램 내부 처리입니다.

핵심 기능은 외부 서버 없이 동작하도록 작성돼 있습니다. 이것은 Chrome 자체의 업데이트·운영체제 동작이나 사용자가 방문한 웹사이트의 통신까지 통제한다는 뜻은 아닙니다. 다른 기기나 다른 Chrome 프로필로 문장이 자동 이동하지 않습니다.

외부 전송이나 동기화를 추가하려면 먼저 처리 목적·데이터·보존·동의 방식을 정의하고, 제품 범위와 이 문서 및 배포 설명을 함께 갱신해야 합니다.

## 권한은 무엇을 위해 요청하나요?

| 선언 | 목적 |
| --- | --- |
| `storage` | 리스트·문장·현재 선택의 로컬 저장과 접근 수준 설정 |
| `clipboardWrite` | 사용자 단축키로 문장을 클립보드에 쓰기 |
| HTTP/HTTPS content script | 일반 웹 페이지에서 단축키·선택 텍스트 처리 |
| `_execute_action` | 팝업 열기 기본 단축키 제안 |

manifest는 `clipboardRead`, `unlimitedStorage`를 요청하지 않습니다. 별도의 `host_permissions` 키 없이 `content_scripts.matches`에 HTTP/HTTPS 패턴을 선언합니다. 넓은 사이트 접근 선언과 실제 처리하는 데이터의 범위를 구분해 설명해야 합니다.

사용자가 사이트 접근을 제한하면 그 사이트에서는 단축키가 작동하지 않을 수 있습니다. 데이터 접근 범위나 권한을 넓힐 때는 필요한 이유를 문서와 스토어 설명에 함께 적습니다.

## 저장소와 입력 보호

현재 구현에서는 background가 저장소를 읽고 쓰며, 팝업과 content script는 검증할 수 있는 요청을 보냅니다. 조회·변경을 순서대로 처리하고 저장이 끝난 뒤 성공 응답을 보냅니다.

현재 소스는 저장소 직접 접근을 `TRUSTED_CONTEXTS`로 제한하도록 요청합니다. 다만 설정 실패를 잡아서 무시하므로 **제한 설정 성공을 코드가 보장하지는 않습니다.** 실제 설정 상태와 실패 처리는 기능 검증 대상입니다.

현재 구현은 읽은 저장 형식과 요청의 필수 값을 검사합니다. 모든 제품 규칙을 읽기·저장 직전에 전수 재검사하거나 발신 환경별 권한을 별도로 검사하는 구조는 아닙니다. 자세한 검증 범위는 [아키텍처](architecture.md)에 설명합니다.

유지해야 할 정책은 다음과 같습니다.

- 저장소·메시지에서 받은 값은 검증한 뒤 사용합니다.
- 잘못된 저장 형식이나 읽기 실패를 빈 데이터로 자동 복구하지 않습니다.
- 사용자 원문을 로그, 오류 응답, 분석 도구에 넣지 않습니다.
- 사용자 텍스트를 HTML로 실행하지 않습니다.
- 새 의존성의 데이터 접근·외부 전송 여부를 검토합니다.

## 복사와 웹 알림에서 보이는 내용

복사는 기존 클립보드를 읽지 않고 저장된 문장을 씁니다. 복사하면 운영체제 클립보드에 문장이 남습니다. C:V에서 원본을 삭제해도 이미 복사한 클립보드 내용이나 다른 앱에 붙여넣은 사본까지 지우지는 않습니다.

웹 알림은 닫힌 Shadow DOM에 일반 텍스트로 렌더링합니다. 복사·저장 성공 알림에는 리스트 이름과 최대 60개 UTF-16 코드 단위의 미리보기가 표시되며 문장 번호는 표시하지 않습니다. 알림 종료 시 host를 제거합니다.

Shadow DOM은 주로 페이지 스타일과 UI를 분리하기 위한 장치입니다. 암호화나 기밀성 보장이 아닙니다. 화면을 보는 사람에게 미리보기가 보이고, 일부 이모지는 미리보기 끝에서 잘릴 수 있습니다. 비밀번호·인증 토큰·비밀 키·민감한 고객 정보 보관용으로 C:V를 사용하지 않습니다.

## 보존과 삭제

| 사용자 동작 | 삭제되는 내용 | 남는 내용 |
| --- | --- | --- |
| 문장 하나 삭제 | 해당 문장 | 같은 리스트의 다른 문장 |
| 문장 전체 삭제 | 현재 리스트 안의 모든 문장 | 현재 리스트 자체, 다른 리스트 |
| 리스트 삭제 | 리스트와 안의 모든 문장 | 다른 리스트. 삭제한 리스트가 현재 선택이면 선택 해제 |
| 팝업 닫기 | 저장하지 않은 초안 등 화면 상태 | 이미 저장한 데이터 |
| 확장 제거 | Chrome이 해당 확장의 로컬 저장 데이터를 삭제 | C:V 외부에 이미 복사한 사본은 별개 |

일반적인 캐시·방문 기록 삭제만으로는 확장 로컬 저장 데이터가 삭제되지 않습니다. Chrome 공식 문서는 `storage.local` 데이터가 확장 제거 시 삭제되고 기본 용량 한도가 10MB라고 설명합니다. C:V는 `unlimitedStorage`를 요청하지 않습니다. [Chrome Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)

Chrome 프로필이나 확장 저장 데이터를 직접 삭제해도 내용을 잃을 수 있습니다. 앱 안의 별도 ‘모든 설정 초기화’ 화면은 없습니다. 삭제된 내용을 되돌리는 휴지통·백업이 없으므로 필요한 원문은 삭제 전에 별도로 보관해야 합니다.

C:V는 저장 내용을 별도로 암호화하지 않습니다. 보호 수준은 Chrome 프로필과 운영체제 계정의 보호에 의존합니다.

## 구버전 데이터

이전 JavaScript 버전은 `legacy-js-final` 태그에 보존돼 있습니다. 현재 TypeScript 구현은 그 버전의 IndexedDB 데이터를 가져오거나 정리하지 않습니다. 현재 소스에는 데이터 이전 코드가 없습니다.

따라서 업데이트해도 예전 문장이 새 목록에 나타난다고 보장할 수 없습니다. 자동 이전이 없다는 것과 옛 데이터를 적극적으로 삭제한다는 것은 다릅니다. 배포 시에는 필요한 문장을 미리 별도로 보관하도록 안내해야 합니다.

## 실패했을 때의 정책

| 상황 | 원칙 |
| --- | --- |
| 조회 실패·지원하지 않는 저장 형식 | 오류를 표시하고 기존 데이터를 자동 초기화하지 않음 |
| 저장 실패·용량 초과 | 성공으로 처리하지 않으며 기존 데이터와 입력 초안 보존 |
| 다른 창에서 리스트 정보 변경 | 오래된 요청을 거부하고 최신 목록 확인 안내 |
| 복사 실패 | 성공 알림을 띄우지 않고 활성 페이지·권한 확인 안내 |

이 원칙의 실제 보장은 실패·동시성·브라우저 재시작 검증이 필요합니다. 이번 작업에서는 코드를 대조했으며 실제 설치된 확장 저장소나 사용자 데이터는 조작하지 않았습니다.
