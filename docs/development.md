# 개발 안내

- 확인일: 2026-10-25
- 소스 기준: `main`의 `605dfa4`

## 개발 준비

Node.js 24 계열과 npm을 사용합니다. 이번 작업 환경은 Node.js `24.19.0`, npm `11.17.0`입니다. 현재 Vite의 Node 요구사항은 `^20.19.0 || >=22.12.0`이며 프로젝트 자체의 `engines`나 `.nvmrc`는 없습니다.

```sh
npm ci
npm run build
```

환경 변수·API 키·백엔드·별도 데이터베이스 설치는 필요하지 않습니다. 최초 패키지 설치에는 네트워크가 필요할 수 있습니다.

## 명령과 실행 환경

| 명령 | 결과 |
| --- | --- |
| `npm run dev` | Vite 개발 서버. `/design/wireframes/`에서 정적 보드 확인 |
| `npm run typecheck` | `src/`의 strict TypeScript 검사 |
| `npm run build` | 타입 검사 → 팝업·background 빌드 → 단일 IIFE content script 빌드. 결과는 `dist/` |
| `npm run preview` | 빌드한 정적 화면을 HTTP로 제공. 확장 API 환경을 대신하지 않음 |

`npm test`·lint 스크립트, 영구 자동 테스트, GitHub Actions는 없습니다. 이전 QA 과정에서 사용한 임시 검사 도구를 현재 테스트 구성으로 간주하지 않습니다. 실제 설치는 [설치·업데이트 안내](release.md#1-빌드와-설치)를 따릅니다.

일반 웹 서버에서 팝업을 열면 확장 API 환경이 없어 데이터 기능을 검증할 수 없습니다. `dist/`를 Chrome에 설치해서 확인합니다. 디자인 보드는 production 빌드에 포함되지 않습니다.

## 변경할 곳 찾기

- 사용자 동작과 제약은 [제품 문서](product.md)를 먼저 읽습니다.
- 실행 영역·메시지·저장 형식은 [아키텍처](architecture.md)를 확인합니다.
- UI 값과 상태 표현은 [디자인 문서](design-system.md)를 확인합니다.
- 데이터나 권한 변경 시 [제품의 데이터 안내](product.md#데이터와-개인정보-요약)와 배포 설명도 함께 수정합니다.
- 저장 규칙 변경은 팝업과 페이지 단축키 경로 모두에 영향을 줍니다. 공통 규칙과 호출자를 함께 확인합니다.

## 문제 해결

| 증상 | 확인과 다음 행동 |
| --- | --- |
| 과거 초기 시작 화면만 보임 | 체크아웃한 브랜치와 확장 설치 경로를 확인합니다. 현재 main은 실제 기능을 포함합니다. |
| 팝업 단축키가 안 됨 | `chrome://extensions/shortcuts`에서 할당·충돌 확인. 아이콘으로 열 수도 있습니다. |
| 리스트 선택·문장 복사가 안 됨 | 입력창 밖에 초점을 두고 현재 리스트·번호와 사이트 접근을 확인합니다. 최상위 HTTP/HTTPS 페이지에서 실행합니다. |
| 선택 텍스트 저장이 안 됨 | 선택 내용·현재 리스트를 확인합니다. 기존 위치 또는 마지막 바로 다음 위치만 저장하며 빈 선택·비밀번호 필드는 제외합니다. |
| “C:V에 연결하지 못했습니다.” | 확장 갱신 후 페이지를 새로고침합니다. 계속되면 확장 활성 상태를 확인합니다. |
| 복사 실패 | 페이지 활성 상태와 클립보드 권한을 확인합니다. 성공 알림 전에 복사됐다고 가정하지 않습니다. |
| 저장 응답을 받지 못함 | 같은 요청을 즉시 재전송하지 말고 ‘저장 결과 확인’ 또는 ‘다시 불러오기’로 실제 저장 결과부터 확인합니다. |
| 리스트 변경 충돌 | 다른 창의 이름·순서·삭제 변경이 있었는지 확인하고 최신 목록을 불러옵니다. |
| 저장소·저장 형식 오류 | 데이터를 자동 초기화하거나 확장을 제거하지 않습니다. 버전·공간·오류를 기록하고 기존 데이터 보존을 우선합니다. |

background는 확장 관리 화면의 service worker 검사, 팝업은 팝업 개발자 도구, content script는 해당 페이지 개발자 도구에서 확인합니다. 실제 사용자 문장이나 전체 저장 데이터를 로그·스크린샷에 남기지 않습니다.

숫자 단축키는 content script가 처리하므로 Chrome 단축키 설정에서 개별 변경할 수 없습니다. 팝업 열기만 Commands API에 등록돼 있습니다. [Chrome Commands 안내](https://developer.chrome.com/docs/extensions/reference/api/commands)

## 검증 범위

이번 문서 변경에서는 현재 소스·설정·기존 QA 기록을 대조했습니다. `npm ci --ignore-scripts --no-audit --no-fund`와 `npm run build`를 실행해 타입 검사와 두 빌드를 통과했습니다. 문서 링크·앵커 66개, 코드 블록, `git diff --check`, 생성된 manifest의 진입 파일·권한과 content script의 구문 검사도 통과했습니다. 별도 에이전트는 문서만으로 제품·사용·데이터·구현·검증 상태의 8개 질문에 답했습니다. 실제 Chrome 팝업·OS 클립보드·웹 단축키는 이번 작업에서 다시 검증하지 않았습니다.

과거 QA의 핵심 흐름·접근성 결과와 미검증 환경은 [QA 기록](qa.md)에 날짜별로 남겨 둡니다. 새 변경이나 의존성 업데이트가 있으면 과거 통과 결과를 그대로 현재 결과로 쓰지 않습니다. 예를 들어 과거 `npm audit` 0건 기록은 현재 취약점 검사를 대신하지 않습니다.

영구 자동 테스트는 사용자 요청으로 이전 작업에서 제거된 상태입니다. 기능 변경 시 필요한 검증은 [Q01~Q17 및 D01~D09](qa.md)에 따라 정하고, 수행한 범위와 미실행 항목을 구분합니다. 문서만 바꾸는 이번 작업에서 테스트 구성이나 제품 코드는 추가하지 않습니다.
