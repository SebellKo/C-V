# 제품 기획 및 범위

- 문서 상태: TypeScript 재구현 기준 v1
- 최종 수정일: 2026-08-29
- 대상 제품: C:V Chrome Extension

## 1. 문서 목적

이 문서는 기존 코드를 보지 않고도 C:V를 다시 구현할 수 있도록 제품 목표, MVP 범위, 사용자에게 보이는 동작과 완료 조건을 정의합니다.

이 문서에서 다루지 않는 내용은 다음과 같습니다.

- framework와 library 선택
- module과 폴더 구조
- popup과 service worker 사이의 구체적인 메시지 형태
- 상태 관리 방식
- 테스트 도구와 배포 pipeline

위 항목은 구현 과정에서 `architecture.md`를 다시 설계하며 결정합니다.

## 2. 제품 한 문장

C:V는 사용자가 자주 쓰는 텍스트를 최대 10개 리스트의 1~10번 command 위치에 저장하고, 웹 페이지에서 단축키로 선택·저장·클립보드 복사할 수 있게 하는 로컬 전용 Chrome 확장 프로그램입니다.

## 3. 해결하려는 문제

블로그, 이메일, 문서, 고객 응대 내용을 작성할 때 사용자는 여러 페이지를 오가며 반복 문장과 고정 양식을 다시 복사합니다. 이 과정은 탭 전환과 마우스 조작이 많고, 복사할 때마다 기존 클립보드 내용이 사라집니다.

C:V는 여러 텍스트를 번호가 있는 위치에 보관해 다음 작업을 줄입니다.

- 반복 문장을 찾기 위한 탭 전환
- 같은 내용을 다시 선택하고 복사하는 작업
- 고정 양식이나 여러 조각의 텍스트를 순서대로 붙여넣는 작업

## 4. 대상 사용자와 환경

### 주요 사용자

- 블로그, 이메일, 문서를 자주 작성하는 사용자
- 반복 문구와 템플릿을 여러 개 사용하는 사용자
- 마우스보다 키보드 단축키를 선호하는 사용자

### 지원 환경

- 최신 안정 버전 Chrome 데스크톱
- macOS를 우선 검증 환경으로 사용
- Windows와 Linux는 Chrome이 제공하는 동일 기능 범위에서 호환 대상으로 두되 MVP 출시 차단 조건으로 삼지 않음
- 일반 `http://`, `https://` 웹 페이지

### 지원하지 않는 환경

- Firefox, Safari 등 다른 브라우저
- 모바일 Chrome
- `chrome://`, Chrome Web Store 등 content script 실행이 제한되는 페이지
- 브라우저 정책이나 사이트 보안 정책으로 clipboard 쓰기가 차단된 환경

## 5. 제품 원칙

1. **로컬 우선**: 계정과 서버 없이 핵심 기능이 동작해야 합니다.
2. **명시적 사용자 동작**: 텍스트 저장과 클립보드 변경은 사용자의 버튼 또는 단축키 동작으로만 발생해야 합니다.
3. **예측 가능한 번호**: popup에 표시된 리스트와 command 위치가 단축키 번호와 일치해야 합니다.
4. **데이터 보존 우선**: 실패한 변경이 기존 정상 데이터를 손상하거나 사용자 입력을 조용히 버리면 안 됩니다.
5. **작은 범위**: 텍스트 저장과 빠른 복사에 집중하며 동기화나 협업 기능을 포함하지 않습니다.

## 6. 용어

| 용어 | 정의 |
| --- | --- |
| 리스트 | command를 묶는 사용자 정의 그룹. 순서와 고유 ID를 가짐 |
| command | 사용자가 저장하고 나중에 클립보드로 복사할 텍스트 |
| command 위치 | 한 리스트의 연속된 command 순서에서 계산되는 1~10번 위치. 단축키 숫자와 직접 대응 |
| 현재 리스트 | 웹 페이지 단축키 동작의 대상이 되는 하나의 리스트 |
| popup | 확장 아이콘 또는 브라우저 단축키로 여는 관리 화면 |
| web toast | popup을 열지 않고 실행한 단축키의 성공 결과를 현재 웹 페이지 위에 잠시 표시하는 비차단 알림 |
| content script | 웹 페이지에서 C:V 단축키와 현재 선택 텍스트를 처리하는 확장 프로그램 코드 |
| 영속 데이터 | popup이나 브라우저를 닫아도 Chrome 프로필에 남는 데이터 |
| 임시 UI 상태 | 열린 modal, 입력 중인 draft처럼 popup을 닫으면 사라져도 되는 데이터 |

## 7. MVP 범위

### 포함

- 리스트 생성, 선택, 이름 변경, 순서 변경, 삭제
- command 생성, 내용 변경, 위치 변경, 삭제, 전체 삭제
- popup에서 리스트와 command 조회 및 관리
- 웹 페이지 단축키로 현재 리스트 선택
- 웹 페이지에서 선택한 텍스트를 번호 위치에 저장
- 번호 위치의 command를 시스템 클립보드에 복사
- 웹 페이지에서 단축키로 선택·복사·저장한 결과를 web toast로 확인
- Chrome 프로필 안의 로컬 영속 저장
- 저장·권한·데이터 오류에 대한 사용자 피드백

### 제외

- 회원가입과 로그인
- 외부 서버 저장
- Chrome Sync를 포함한 기기 간 동기화
- 공유 리스트와 협업
- 이미지, 파일, HTML 서식 등 일반 텍스트 이외의 command
- clipboard 내용 읽기 또는 clipboard history
- 브라우저 입력창에 텍스트를 자동으로 붙여넣는 기능
- command 검색, 태그, 폴더, 즐겨찾기
- 변경 이력, 휴지통, 서버 백업
- 암호 관리자 또는 비밀정보 보관 기능
- 사용 분석, 광고, 원격 오류 수집

## 8. 기능 요구사항

### 8.1 popup 시작

- `APP-001` popup을 열면 저장된 리스트와 현재 리스트를 불러옵니다.
- `APP-002` 초기 조회가 끝나기 전의 빈 상태와 실제 데이터가 없는 상태를 구분합니다.
- `APP-003` 초기 조회에 실패하면 빈 데이터로 덮어쓰지 않고 재시도 가능한 오류를 표시합니다.
- `APP-004` popup을 닫으면 modal과 입력 draft 같은 임시 상태는 폐기합니다.
- `APP-005` popup을 다시 열면 영속 저장소의 최신 데이터로 화면을 다시 구성합니다.
- `APP-006` popup viewport는 `300 × 380px`로 고정하며 목록이 길어지면 지정된 content 영역만 세로로 scroll합니다.

### 8.2 리스트 관리

- `LIST-001` 사용자는 popup에서 새 리스트를 생성할 수 있습니다.
- `LIST-002` 리스트는 최대 10개까지 저장할 수 있습니다.
- `LIST-003` 리스트 이름은 앞뒤 공백을 제거한 뒤 1자 이상 100자 이하여야 합니다.
- `LIST-004` 공백만 있는 리스트 이름은 허용하지 않습니다.
- `LIST-005` 정규화된 리스트 이름은 대소문자를 구분해 서로 달라야 합니다.
- `LIST-006` 리스트 ID는 생성 후 이름이나 순서가 바뀌어도 유지됩니다.
- `LIST-007` 사용자는 리스트 이름과 표시 순서를 변경할 수 있습니다.
- `LIST-008` 사용자는 리스트를 삭제할 수 있으며 해당 리스트의 command도 함께 삭제됩니다.
- `LIST-009` 현재 리스트를 삭제하면 현재 리스트 선택을 해제합니다.
- `LIST-010` 저장에 실패하면 popup의 목록을 성공한 것처럼 확정하지 않습니다.
- `LIST-011` 리스트 순서 변경과 삭제 후 표시 순서는 1번부터 빈 번호 없이 다시 정렬합니다.
- `LIST-012` 이름을 현재 값과 같게 저장하는 동작은 중복 오류가 아닌 변경 없음으로 처리합니다.
- `LIST-013` 리스트를 다른 리스트 위치에 drop하면 대상 위치에 삽입하고 나머지 리스트를 앞이나 뒤로 한 칸씩 이동합니다.
- `LIST-014` 리스트 DnD는 drag handle로 시작하며 keyboard와 위로·아래로 이동 action으로도 같은 순서 변경을 수행할 수 있어야 합니다.

### 8.3 현재 리스트

- `CURRENT-001` 현재 리스트는 없거나 정확히 하나입니다.
- `CURRENT-002` popup에서 리스트를 선택하면 영속 저장 성공 후 화면의 현재 리스트를 변경합니다.
- `CURRENT-003` 저장된 현재 리스트 ID가 실제 리스트에 없으면 선택을 해제합니다.
- `CURRENT-004` 리스트 이름과 순서를 변경해도 현재 리스트는 같은 ID를 기준으로 유지됩니다.
- `CURRENT-005` 현재 리스트가 없으면 command 저장·복사 단축키는 아무 데이터도 변경하지 않습니다.

### 8.4 command 관리

- `COMMAND-001` 각 리스트는 최대 10개의 command를 가지며 command 위치는 1번부터 현재 개수까지 빈 번호 없이 이어집니다.
- `COMMAND-002` command는 일반 텍스트이며 여러 줄을 포함할 수 있습니다.
- `COMMAND-003` 공백만 있는 command는 저장하지 않습니다.
- `COMMAND-004` 유효한 command의 앞뒤 공백과 줄바꿈은 사용자가 입력하거나 선택한 그대로 보존합니다.
- `COMMAND-005` 같은 리스트 안에서 완전히 같은 command 텍스트를 중복 저장하지 않습니다.
- `COMMAND-006` 서로 다른 리스트에는 같은 command를 저장할 수 있습니다.
- `COMMAND-007` popup에서 새 command를 추가하면 현재 목록의 마지막 위치에 저장합니다.
- `COMMAND-008` 사용자는 command 내용과 표시 순서를 변경할 수 있습니다.
- `COMMAND-009` 위치가 바뀌면 해당 command에 대응하는 숫자 단축키도 즉시 바뀝니다.
- `COMMAND-010` command를 삭제하면 뒤에 있던 command를 한 칸씩 앞으로 당겨 위치를 다시 부여합니다.
- `COMMAND-011` 전체 삭제는 현재 리스트의 command만 삭제하고 리스트는 유지합니다.
- `COMMAND-012` command 목록에는 빈 위치, `null`, `dummy` 문자열 같은 placeholder를 저장하지 않습니다.
- `COMMAND-013` command의 별도 글자 수 상한은 두지 않으며 Chrome 저장소 한도 초과 시 기존 데이터를 보존하고 오류를 표시합니다.
- `COMMAND-014` 현재 위치의 command를 같은 값으로 저장하는 동작은 중복 오류가 아닌 변경 없음으로 처리합니다.
- `COMMAND-015` command를 다른 command 위치에 drop하면 source와 target 두 command의 위치만 서로 교환합니다.
- `COMMAND-016` command DnD는 대상 위치에 삽입해 중간 command를 밀거나 빈 위치를 만들지 않습니다.
- `COMMAND-017` 같은 위치 또는 목록 밖에 drop하면 순서와 영속 데이터를 변경하지 않습니다.
- `COMMAND-018` command DnD는 drag handle로 시작하며 keyboard와 위로·아래로 이동 action은 인접한 command와 위치를 교환합니다.
- `COMMAND-019` drag 중 화면은 교환될 위치를 미리 표시할 수 있지만 유효한 drop 뒤 영속 저장에 성공해야 변경을 확정합니다.

### 8.5 단축키

숫자 `1`부터 `9`는 1~9번 위치이고 숫자 `0`은 10번 위치입니다.

| 동작 | 단축키 | 결과 |
| --- | --- | --- |
| popup 열기 | macOS `Command+B`, Windows/Linux `Ctrl+B` | Chrome이 popup을 열거나 닫음 |
| 현재 리스트 선택 | `Shift+숫자` | 해당 순서의 리스트를 현재 리스트로 저장 |
| command 복사 | `Alt+숫자` (`Option+숫자` on macOS) | 현재 리스트의 해당 위치 텍스트를 clipboard에 씀 |
| 선택 텍스트 저장 | `Shift+Alt+숫자` (`Shift+Option+숫자` on macOS) | 현재 웹 페이지의 선택 텍스트를 해당 command 위치에 저장 |

- `SHORTCUT-001` 정확한 modifier와 숫자 조합만 처리하고 일반 키 입력은 수집하거나 저장하지 않습니다.
- `SHORTCUT-002` 존재하지 않는 리스트 번호 또는 command 복사 위치는 오류로 페이지 동작을 방해하지 않고 아무 작업도 하지 않습니다.
- `SHORTCUT-003` 선택 텍스트 저장은 단축키를 누른 시점의 현재 선택 영역만 사용합니다.
- `SHORTCUT-004` 선택된 텍스트가 없거나 공백뿐이면 기존 command를 변경하지 않습니다.
- `SHORTCUT-005` 선택 텍스트 저장 위치가 기존 command 위치이면 해당 값을 교체하고, 현재 마지막 command의 바로 다음 위치이면 새 command로 추가합니다.
- `SHORTCUT-006` 선택 텍스트 저장 위치가 현재 마지막 command보다 두 칸 이상 뒤이면 빈 위치를 만들지 않고 아무 작업도 하지 않습니다.
- `SHORTCUT-007` 같은 리스트의 다른 위치에 동일한 command가 있으면 중복 저장하지 않습니다.
- `SHORTCUT-008` command 복사는 clipboard에 쓰기만 하며 웹 페이지 입력창에 자동으로 붙여넣지 않습니다.
- `SHORTCUT-009` 페이지의 기본 동작을 막아야 한다면 C:V가 실제로 작업을 처리한 경우에만 막습니다.
- `SHORTCUT-010` Chrome 또는 웹 페이지의 단축키 충돌로 동작하지 않을 수 있으며 사용자가 Chrome 확장 프로그램 단축키 설정에서 확인할 수 있게 안내합니다.
- `SHORTCUT-011` popup을 열지 않고 웹 페이지에서 단축키 작업이 성공하면 content script가 현재 페이지 위에 web toast를 표시합니다.
- `SHORTCUT-012` 리스트 선택 성공 toast는 선택된 리스트 이름을 표시합니다.
- `SHORTCUT-013` command 복사 성공 toast는 현재 리스트 이름, command 번호와 command 내용 미리보기를 표시합니다.
- `SHORTCUT-014` 선택 텍스트 저장 성공 toast는 현재 리스트 이름, 저장한 command 번호와 내용 미리보기를 표시합니다.
- `SHORTCUT-015` command 미리보기는 줄바꿈을 공백으로 바꾸고 최대 60자까지만 사용해 페이지 위에 전체 내용을 오래 노출하지 않습니다.
- `SHORTCUT-016` 작업이 실제로 성공한 뒤에만 성공 toast를 표시하며 존재하지 않는 번호처럼 기존 정책상 no-op인 입력에는 표시하지 않습니다.

### 8.6 modal과 사용자 피드백

- `UI-001` 생성·수정 modal은 확인과 취소 동작을 제공합니다.
- `UI-002` 유효성, 중복, 최대 개수, 저장 실패를 구분해 사용자가 이해할 수 있는 한국어 메시지를 표시합니다.
- `UI-003` 검증 또는 저장에 실패하면 modal을 닫거나 입력 draft를 지우지 않습니다.
- `UI-004` 저장 성공 후에만 modal을 닫고 최신 영속 데이터를 화면에 반영합니다.
- `UI-005` 삭제처럼 되돌리기 어려운 작업은 대상과 영향을 명확하게 표시합니다.
- `UI-006` 버튼과 입력 요소는 키보드로 접근할 수 있고 의미 있는 label과 focus 표시를 가집니다.
- `UI-007` 긴 command는 목록에서 일부만 미리 보여줄 수 있지만 저장 내용을 자르지 않으며 편집 화면에서는 전체 텍스트를 표시합니다.
- `UI-008` modal 내용이 popup 높이를 넘으면 modal 내부 내용만 scroll하고 확인·취소 action은 접근 가능한 위치에 유지합니다.
- `UI-009` 저장 중에는 같은 요청을 중복 실행할 수 없게 하고 진행 상태를 표시합니다.
- `UI-010` 사용자가 저장 응답 전에 popup을 닫더라도 이미 Background에 전달된 요청은 popup 생명주기와 별개로 완료하며 다음 popup에서 영속 결과를 다시 읽습니다.
- `UI-011` web toast는 viewport 하단 중앙에서 16px 떨어진 위치에 표시하고 페이지 입력이나 클릭을 막지 않습니다.
- `UI-012` web toast는 2.5초 뒤 자동으로 사라지며 닫기 버튼이나 별도 action을 제공하지 않습니다.
- `UI-013` toast가 표시된 동안 새 성공 결과가 오면 여러 개를 쌓지 않고 최신 내용으로 교체한 뒤 표시 시간을 다시 시작합니다.
- `UI-014` web toast는 페이지 CSS와 충돌하지 않는 격리된 style 범위에서 렌더링하며 viewport 폭이 좁으면 좌우 16px 여백을 유지합니다.
- `UI-015` web toast는 비긴급 성공 피드백이므로 `role="status"`와 `aria-live="polite"`를 사용하고, 모션 감소 설정에서는 이동 animation 없이 표시합니다.

## 9. 핵심 사용자 흐름

### 9.1 popup에서 처음 설정

1. 사용자가 popup을 엽니다.
2. 저장된 데이터가 없으면 빈 상태를 표시합니다.
3. 사용자가 리스트를 생성합니다.
4. 생성된 리스트를 현재 리스트로 선택합니다.
5. 사용자가 command를 순서대로 추가합니다.
6. popup을 닫았다가 다시 열어도 저장한 내용과 현재 리스트가 유지됩니다.

### 9.2 선택 텍스트 저장

1. 사용자가 일반 웹 페이지에서 텍스트를 선택합니다.
2. `Shift+Alt+숫자`를 누릅니다.
3. content script가 그 시점의 선택 텍스트와 숫자 위치를 service worker에 전달합니다.
4. service worker가 현재 리스트와 입력을 검증한 뒤 영속 저장합니다.
5. 실패하면 기존 command를 유지합니다.
6. 성공하면 페이지 toast에서 현재 리스트, 저장한 command 번호와 내용 미리보기를 확인합니다.
7. 다음에 popup을 열면 저장된 텍스트가 같은 번호 위치에 표시됩니다.

### 9.3 command 사용

1. 사용자가 `Shift+숫자`로 현재 리스트를 선택합니다.
2. 저장 성공 후 페이지 하단 toast에서 선택된 리스트 이름을 확인합니다.
3. `Alt+숫자`로 해당 위치의 command를 clipboard에 복사합니다.
4. clipboard 쓰기 성공 후 toast에서 현재 리스트, command 번호와 내용 미리보기를 확인합니다.
5. 사용자가 원하는 입력창에서 시스템 붙여넣기 명령을 실행합니다.

### 9.4 리스트 metadata 편집

1. 사용자가 popup에서 리스트 이름, 순서, 삭제 대상을 편집합니다.
2. 확인 시 변경 의도만 저장 계층에 전달합니다.
3. 저장 직전의 최신 리스트에 이름·순서·삭제를 반영합니다.
4. 동시에 변경된 command는 보존합니다.
5. 성공 후 최신 데이터를 다시 읽어 popup에 표시합니다.

## 10. 오류와 경계 조건

| 상황 | 기대 동작 |
| --- | --- |
| 저장소 조회 실패 | 빈 상태로 덮어쓰지 않고 오류와 재시도 제공 |
| 저장 실패 | 성공 응답과 성공 UI를 표시하지 않고 기존 영속 데이터 유지 |
| 저장 데이터 형식 오류 | 자동 초기화하지 않고 안전하게 중단해 복구 가능성 보존 |
| 동시에 두 변경 요청 발생 | 한 변경이 다른 변경을 유실하지 않도록 순서대로 반영 |
| 선택된 리스트 삭제 | 현재 리스트를 `없음`으로 변경 |
| 없는 리스트 또는 위치 요청 | 데이터 변경 없이 안전하게 실패하거나 no-op 처리 |
| 중복 이름 또는 command | 기존 데이터 유지, 사용자에게 원인 표시 |
| 최대 개수 초과 | 기존 데이터 유지, 최대 개수 안내 |
| popup이 저장 중 닫힘 | 성공 응답 전에 저장을 취소한 것으로 간주하지 않으며 다음 popup에서 영속 결과를 기준으로 복원 |

## 11. 데이터와 상태의 제품 계약

- 영속 데이터의 원본은 Chrome 프로필의 로컬 확장 저장소입니다.
- popup의 화면 상태는 영속 데이터의 임시 스냅샷이며 별도의 원본이 아닙니다.
- 변경 요청은 영속 저장 성공 후에만 성공으로 간주합니다.
- popup을 열 때와 성공한 변경 뒤에는 영속 저장소의 최신 데이터를 기준으로 화면을 구성합니다.
- command는 빈 위치 없는 연속 목록으로 저장하며 화면 번호와 단축키 번호는 목록 순서에서 계산합니다.
- 리스트와 command의 표시 순서는 저장과 재시작 이후에도 동일해야 합니다.
- 개인정보와 데이터 처리 세부사항은 [데이터 및 개인정보 정책](./data-privacy-policy.md)을 따릅니다.

## 12. 비기능 요구사항

- `NFR-001` handwritten production source는 TypeScript로 작성하고 strict type checking을 사용합니다.
- `NFR-002` Chrome Extension Manifest V3를 사용합니다.
- `NFR-003` 핵심 기능은 네트워크 연결 없이 동작합니다.
- `NFR-004` 외부 계정, 서버, 분석 SDK를 요구하지 않습니다.
- `NFR-005` 사용자 command와 리스트 이름을 log에 출력하지 않습니다.
- `NFR-006` 저장과 RPC 입력은 런타임에서도 검증합니다.
- `NFR-007` content script가 필요한 권한과 웹 페이지 접근 범위를 최소화합니다.
- `NFR-008` build 결과물 이외의 production source에 JavaScript 파일을 새로 추가하지 않습니다.
- `NFR-009` popup을 닫거나 service worker가 다시 시작돼도 영속 데이터가 유지됩니다.
- `NFR-010` 저장량이 작다는 현재 한도 안에서 정확성과 단순성을 성능보다 우선합니다.

## 13. MVP 완료 조건

- 빈 설치에서 리스트 생성부터 command clipboard 복사까지 핵심 흐름이 동작합니다.
- 리스트와 command의 최대 개수, 중복, 빈 값 규칙이 popup과 단축키 경로에서 동일하게 적용됩니다.
- 리스트 이름·순서 편집과 command 변경이 동시에 발생해도 어느 쪽도 유실되지 않습니다.
- 현재 리스트를 삭제한 뒤 잘못된 선택 상태가 남지 않습니다.
- popup 재실행과 service worker 재시작 뒤에도 데이터와 순서가 유지됩니다.
- 저장 실패 시 modal draft와 기존 영속 데이터가 유지됩니다.
- 지원하는 모든 단축키가 popup에 표시된 번호와 동일하게 동작합니다.
- 성공한 웹 페이지 단축키는 선택된 리스트와 command를 toast로 확인할 수 있습니다.
- 민감정보가 외부로 전송되거나 log에 노출되지 않습니다.
- 제품 동작과 데이터 정책을 검증하는 자동 테스트 및 macOS Chrome 수동 검증이 완료됩니다.
